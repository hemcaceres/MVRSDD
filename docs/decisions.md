# Decisiones del producto

Todavía no hay decisiones de producto registradas. Anotar sólo decisiones que afecten alcance, reglas, arquitectura, proveedores, seguridad o datos. Las decisiones menores de implementación se explican en spec/evidencia cuando sea útil.

Por decisión: ID estable, fecha, contexto/pregunta, alternativas relevantes, resolución o pendiente, fundamento, quién decide y referencia del acuerdo cuando requiera autoridad humana. Identificar límites de una delegación expresa. No convertir una propuesta del PRD en decisión aprobada.

Las dependencias abiertas se referencian desde la spec y el catálogo. No duplicar aquí la aprobación o fase de cada feature. Al resolver una decisión, actualizar su entrada y conservar antecedentes fechados si aportan contexto.
